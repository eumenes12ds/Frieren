# リクエスト方式

## 方式による違い

### 順番にリクエストし、失敗したら再試行

物語を生成し直す場合と同じように、次の手順で処理します。

- AIへ一度リクエストします。
- 返信に変数更新コマンドがあれば、それで変数を更新します。
- なければ、設定したリクエスト回数に達するまで再試行します。

### 同時に複数回リクエスト

**指定した回数のリクエストを同時に送信**します。

- 設定した回数だけ、AIへのリクエストを同時に開始します。
- いずれかの返信に変数更新コマンドが含まれていれば、それで更新し、まだ完了していないほかのリクエストを中断します。

待ち時間を短縮できますが、同時送信した分だけ追加のトークンを消費します。Claudeなどトークンキャッシュに応じて課金するモデルでは、次の方式も使えます。

### 最初に一度だけリクエストし、失敗したら同時に複数回リクエスト

まず一度だけ送信し、失敗した場合に同時に複数回送信します。

## 同時リクエストを使う場面

モデルの毎分リクエスト数（rpm）に余裕があれば、同時送信または一度試行した後の同時送信を選べます。

## 同時リクエストのトークン消費

追加モデル解析で使うプロンプトは、次のものに限られます。

- 名前に`[mvu_update]`を含むワールドブック項目。
- 名前に`[mvu_plot]`も`[mvu_update]`も含まないワールドブック項目。
- **最後の2階層のメッセージだけ**。
- プリセット送信を選んだ場合は、そのプリセットのプロンプトも含まれます。

通常のチャットでは履歴が多くのトークンを占めますが、追加モデル解析が参照するのは最後の2階層です。そのため、カード側のワールドブックが適切に設計されていれば、一括リクエストで消費が過度に増えることは通常ありません。
